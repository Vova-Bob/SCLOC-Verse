# Settings Hub — Дизайн-система

> Цей документ визначає **не вигляд однієї сторінки, а правила, за якими будується
> будь-яка сторінка налаштувань** SCLOC-Verse. Settings Hub — це дизайн-система,
> а не окремий екран. Кожна нова категорія автоматично успадковує ці правила й
> виглядає правильно без окремого дизайну.
>
> Картка-індекс: KB §17.7. Архітектурне рішення: ADR-009. Функціональна специфікація:
> [`settings-hub.md`](settings-hub.md). Макети-еталон: `.kilo/settings-mockups/`.

**Центр керування** — це інтерфейс, який показує стан продукту й дозволяє ним
керувати, а не лише змінює параметри.

---

## 1. Коренева причина

Реалізація Phase 0 виглядає як **стара сторінка налаштувань** (`SettingsCanvas`),
якій зліва додали меню навігації. Натомість затверджена концепція вимагає, щоб Hub
сприймався як **окремий центр керування продуктом**.

Settings Hub має виглядати як новий окремий центр керування, а не як стара сторінка
налаштувань із доданим меню навігації.

## 2. Наслідки (що пішло не так)

Реалізація успадкувала ДНК старої сторінки налаштувань замість того, щоб втілити
центр керування. Це виявляється так:

- **Контроли** — чекбокси замість тоглів; README-блок, якого немає в концепції.
- **Стан продукту прихований** — немає бейджів середовищ (LIVE/PTU/EPTU),
  немає статус-крапок overlay.
- **Стиль скидання** — кнопка «скинути» виглядає як небезпечне видалення.
- **Щільність** — усе стиснуто, мало простору; сторінка «важка».
- **Контраст** — тони зливаються, групи не відокремлюються, текст читається гірше.
- **Вирівнювання** — контролі «плавають», немає єдиної колонки.
- **«Головна»** — реалізована як категорія-пустушка, а не навігація повернення.
- **Індикатор активної категорії** — оголошений, але невидимий.

Усе перелічене — **наслідки** однієї причини: відсутності ідентичності центру
керування. Не окремі баги, а прояв одного розриву.

## 3. Принципи дизайн-системи

### P0. Identity First — головне правило

Settings Hub має сприйматись як окремий центр керування продуктом, а не як стара
сторінка налаштувань із доданим меню навігації.

Усі наступні принципи — наслідки P0. Якщо рішення суперечить P0, воно хибне.

### P1. Reset — не видалення

«Скинути» — оборотна дія (повернутись до типового), а не втрата даних. Небезпечне
(червоне) стилізування зарезервоване для деструктивних дій. Reset оформлюється
нейтрально: ↺ glyph, приглушений колір, hover-підтвердження.

### P2. Простір як ієрархія

Вільний простір — не порожнеча, а інструмент. Він створює спокій, ієрархію й
відчуття делікатності. Стисненість виглядає утилітарно. Відступи мають бути
щедрими, як у затверджених макетах.

### P3. Контраст і відокремлення

Групи мають чітко відокремлюватись фоном та/або рамкою. Використовуються три
шари глибини (глибокий фон / картка / рядок) + м’які межі. Без контрасту елементи
зливаються в єдину масу.

### P4. Єдина колонка контролов

Усі контролі дії (тогли, кнопки, селектори) розташовуються в одній правій колонці
на одній вертикальній лінії. Це дає сканованість і порядок. Контролі не «плавають».

### P5. Progressive Disclosure

Користувач має бачити лише те, що може використати зараз. Майбутній функціонал не
створює інформаційного шуму.

Саме тому в Phase 0 відсутні: окремі категорії «Діагностика» й «Оновлення»
(згорнуті у «Загальне»), редактор гарячих клавіш (немає persistence),
налаштування Anti-AFK (інструмент не активний), порожній «Профіль», нефункціональний
пошук. Це не прогалини — це свідома політика. Будь-який новий елемент додається
лише коли за ним стоїть реалізований функціонал.

## 4. Спільний набір (Design Kit)

Усе нижче — те, що кожна сторінка налаштувань успадковує автоматично.
Не проєктується наново для кожної категорії.

| Елемент | Правило |
|---|---|
| **Каркас сторінки** | заголовок категорії + підзаголовок-лічильник + описовий рядок + прокручувана зона з групами + нижній рядок скидання категорії |
| **Група** | малий uppercase-заголовок (зі збільшеним міжлітерним інтервалом) + рядки/поля всередині; групи чітко відокремлені |
| **Рядок налаштування** | ліворуч — назва + опис; праворуч — контрол у єдиній колонці (P4) |
| **Тогл** | єдиний перемикач «Увімк/Вимк» для всіх булевих параметрів (не чекбокс) |
| **Скидання** | ↺ glyph, нейтральний стиль (P1): per-control та per-category |
| **Статус продукту** | бейджі/крапки стану видимі (середовища, активні оверлеї, синхронізація) |
| **Шкала відступів** | єдина для всіх сторінок (P2) |
| **Палітра** | єдині шари глибини + м’які межі (P3) |
| **«Головна»** | навігація повернення (вихід з Hub), не категорія |

Коли додається нова категорія — вона береться з цього набору, а не дизайнується з нуля.

## 5. Критерій завершення (UX Polishing)

Фаза вважається завершеною не тоді, коли закрито список пунктів, а тоді, коли
**сліпий перегляд впізнає Settings Hub як окремий центр керування, а не як стару
сторінку налаштувань із меню** (P0).

Перевірочні питання:
1. Чи впізнається Hub як центр керування з першого погляду?
2. Чи видний стан продукту (не лише параметри)?
3. Чи достатньо простору й контрасту для спокійного читання?
4. Чи всі контролі в єдиній правій колонці?
5. Чи всі скидання виглядають нейтрально (не як видалення)?
6. Чи немає жодного елемента без реалізованого функціоналу (P5)?
