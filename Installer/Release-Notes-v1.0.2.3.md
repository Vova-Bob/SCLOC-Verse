# SCLOC-Verse v1.0.2.3

## Що нового

### Безпека

- **SEC-12: Закрито критичну уразливість SECURITY DEFINER** — будь-який авторизований користувач міг викликати адміністративні функції бази даних (видалення телеметрії, керування інцидентами) через REST API. Доступ обмежено лише Control Center.

- **SEC-11: Додано `SET search_path`** для двох пропущених функцій (`set_knowledge_change_context`, `set_incident_code`) — остаточно закрито попередження Security Advisor.

### Стабільність (RC-401 Defense-in-Depth)

- **C — Перевірка терміну дії JWT** — перед кожною відправкою телеметрії перевіряється, чи не протух access token. Якщо токен прострочений — запити не відправляються взагалі, що запобігає 401 storm на корені.

- **D — Зупинка телеметрії при втраті авторизації** — при події `SignedOut` фоновий таймер відправки телеметрії зупиняється. При повторному вході — відновлюється.

- **D+ — Зупинка в catch-блоках** — додано `_telemetry.Stop()` у обробники помилок `RestoreSession` та `SignIn`, бо SDK не завжди генерує подію `SignedOut` при помилці оновлення токена (напр. `refresh_token_already_used`).

- **F — Пакетна відправка телеметрії** — замість 100 окремих HTTP-запитів тепер відправляється 1 пакетний запит. Зменшує навантаження на сервер у 100 разів.

### Продуктивність бази даних

- **RLS Init Plan** — оптимізовано 10 RLS-політик: `auth.uid()` замінено на `(SELECT auth.uid())` для кешування результату (одне обчислення на запит замість обчислення для кожного рядка).

- **FK Indexes** — додано 7 індексів на зовнішні ключі для прискорення операцій DELETE CASCADE/SET NULL.

- **Очищення резервних схем** — видалено `backup_pre_1_0_0_1` та `backup_pre_phase3a` (23 таблиці, ~488 KB, 0 залежностей).
