# SCLOC-Verse 1.0.2.5 — Telemetry Pipeline Hardening

## Що нового

### Критичне виправлення телеметрії

Виявлено та усунуто **ланцюг дефектів** у телеметрії, який міг призвести до:
- втрати валідних подій спостережуваності;
- нескінченного циклу повторних спроб при помилках БД;
- блокування всієї черги подій одним проблемним записом.

### Зміни

**Тришаровий захист Failed-подій:**

1. **Source (13 шляхів):** усі місця створення `Failed`-подій гарантовано заповнюють signal-поля (source, exception_type). Закрито: BackgroundUpdateMonitor (4), AuthService (4), UpdateEvents (4), LiaEvents (1).

2. **BuildEvent (централізована валідація):** `TelemetryClient.BuildEvent()` перевіряє інваріант `Failed → має signal` перед постановкою в чергу. При порушенні — авто-доповнення.

3. **Uploader (ізоляція + retry):**
   - **Poison eviction:** лічильник повторних спроб (max 3). Після вичерпання — подія скидається.
   - **Batch isolation (Variant D):** бінарний поділ батчу для пошуку poison event. Валідні події зберігаються, poison — індивідуально підтверджується і скидається.
   - **403 no-retry:** GitHub API 403 більше не повторюється (retry не допомагає при rate limit).

**Інші виправлення:**
- Виправлено сповіщення про автооновлення локалізації (`InstallAsync` не передавав `HasUpdate`).
- Інтервал фонової перевірки зменшено з 60 хв до 10 хв.
- Алгоритм `BatchIsolation` виділено в testable generic class.
- Додано 22 автоматизованих тести (xUnit).

### Сумісність

### Відомі обмеження

- При transient error (мережа/timeout) під час isolation — події втрачаються (best-effort, Стаття 1 Конституції Observability).
- Redundant retry у isolation (1 зайвий HTTP-запит) — прийнятний компроміс за простоту коду.
